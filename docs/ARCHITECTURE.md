# Архитектура проекта (Defold 1.14.0)

Игра: мобильный пошаговый бесконечный dungeon crawler (см. `GDD.md`). Прототип без графики: заглушки-прямоугольники и текст.

---

## 1. Принципы

1. **Ядро отделено от движка.** Правила игры — в `core/`, чистый Lua без Defold API. Скрипты Defold связывают ядро с экраном.
2. **Мир бесконечен, память ограничена.** В памяти окно рядов и ряд точки возврата. Ряды выше точки возврата генерируются по требованию из `row_seed(world_seed, respawn_count, y)` (GDD 11).
3. **Сущности через реестр.** Типы клеток, врагов, экипировки, боссов и рядов добавляются записями в реестр, без правок ядра (`docs/ENTITY_REGISTRY.md`).
4. **Данные — только из баланса.** Числа берутся из `core/data/balance.lua`, сгенерированного из `balance/balance.csv` (`docs/BALANCE.md`).
5. **Физика не используется.** Поле — сетка, попадания считаются по координатам.
6. **Одна игровая коллекция.** Мир, лагерь и арена босса — состояния одного мира, а не отдельные уровни. Переходы не требуют выгрузки мира.

## 3. Слои и правило зависимостей

```
main, collections, game_objects, gui     (Defold-скрипты)
            │
            ▼
        scripts/                         (хелперы Defold)
            │
            ▼
        core/                            (правила игры)
            │
            ▼
        core/data/balance.lua            (сгенерировано)
```

Запрещено:
- `core/` вызывает `go.*`, `msg.*`, `gui.*`, `sys.*`, `factory.*`, `render.*`, `timer.*`.
- `game_objects/` напрямую меняет состояние мира. Только через сообщения в `world`.
- Скрипты одной коллекции напрямую читают поля друг друга. Только сообщения.
- `core/registry/*` импортирует `core/data/balance.lua`, но не `core/run.lua`. Обработчики получают контекст `ctx`, а не модуль хода.

## 4. Состояния приложения

```
BOOT
 └─▶ WORLD  (бесконечный мир; ход игрока; точка возврата)
      ├─▶ CAMP   (лагерь: восстановление, прокачка, экипировка) ─▶ WORLD
      ├─▶ BOSS   (арена босса, два ряда)                       ─▶ CHECKPOINT ─▶ WORLD
      └─▶ DEATH  (экран смерти)                                 ─▶ WORLD (в точке возврата)
```

- `WORLD`, `CAMP`, `BOSS`, `DEATH` — режимы одного мира, а не отдельные коллекции уровня. Переход меняет режим в `core/world.lua` и показывает нужный GUI.
- Владелец режима — `core/world.lua`. Скрипты не решают сами, куда перейти.
- Таблица переходов — в `core/world.lua`, тестируется без движка.
- `main.script` отвечает за старт, загрузку сохранения и фоновый режим.

## 5. Поток данных хода

```
тап (world.script)
   │
   ▼
scripts/input.lua    экранная точка -> клетка (x, y)
   │
   ▼
core/run.lua         порядок шагов GDD §5.2; возвращает список событий
   │                 при смерти: core/death.lua -> восстановление в точке возврата
   ▼
world.script         проигрывает события: анимации, текст, смена состояния клеток
```

`core/run.lua` возвращает список событий, например `{ type = "move", from = {x, y}, to = {x, y} }`. Скрипт превращает события в анимации и сообщения объектам. Ход тестируется без движка и без таймингов.

Длительности анимаций (`anim.*`) — в `design/design.csv`, не в скриптах.

## 6. Ряды, окно и память

- **Окно рядов:** `core/world.lua` держит ряды от `current_row − W` до `current_row + W` (W — в CSV, небольшое число). Ряды вне окна выгружаются из памяти и генерируются заново по требованию.
- **Seed ряда:** `core/row_seed.lua` — `f(global_seed, row_index)`. Один и тот же ряд всегда генерируется одинаково.
- **Ряды выше точки возврата:** генерируются по `row_seed(world_seed, respawn_count, y)`. После возрождения пересоздаются (`respawn_count` растёт). Журнала изменений нет (GDD 11).
- **Визуальные объекты:** клетки создаются фабрикой для рядов в окне и удаляются при выходе за окно. Не все ряды существуют как игровые объекты одновременно.
- **Прокрутка:** мир сдвигается по `y`, чтобы текущий ряд оставался в видимой части экрана. Прокрутка — свойство контейнера рядов.

Точка возврата и журнал проверяются тестами на память: число хранимых рядов не растёт с номером текущего ряда (см. `TESTING.md`).

## 7. Экран и поле

- Логические координаты: `x` 0..4 (5 колонок), `y` — номер ряда в мире (0 — стартовый, растёт вверх).
- Экранные координаты: поле центрируется по ширине; размеры — логические (`screen.*` в `design/design.csv`).
- Камера: без `camera`-компонента. Прокрутка — сдвиг контейнера рядов.
- HUD — отдельная коллекция `gui`, не двигается.
- Слой угроз (GDD §5.4) считается в `core/highlight.vision` и рисуется полупрозрачными прямоугольниками (bar-фабрика) поверх клеток (z-слой), но под персонажами и содержимым; клетка игрока в поле зрения — красная, поверх спрайта игрока. Пересчёт — при каждой перерисовке окна (движение игрока, смерть врага).

## 8. Коллекции и объекты

- `main.collection` — только `main.script`. Игровых объектов нет.
- `world.collection` — контейнер рядов, `player`, `hud` (GUI-компонент).
- `camp.collection`, `death`: GUI-экраны поверх мира. Мир не выгружается.
- Босс: объекты арены создаются при входе в режим `BOSS` и удаляются при выходе. Не вложены в мир как постоянные.
- Фабрики: клеток (по типу), врагов, босса. Один прототип на тип.
- Имена объектов стабильны: клетка — `cell_<x>_<y>` в пределах окна; враг — `enemy_<id>`, id выдаёт `core/world.lua`.

---

## 9. Ввод

- `on_input` только в скриптах, которые принимают ввод: `world.script` (клетки), `camp.gui_script`, `death.gui_script`.
- Если тап обработан, вернуть `true`, иначе `false`.
- Во время хода ввод блокируется флагом `world.input_locked`, а не проверкой анимаций.
- Тап вне поля и вне кнопок игнорируется.

---

## 10. Сохранения

Сохраняется (GDD §18): золото, прокачка, экипировка, точка возврата, журнал рядов выше неё, глобальный seed.

- Файл: `sys.save` через `scripts/saves.lua`.
- Структура (версия 2): `{ version = 2, seed = N, respawn_count = N, gold = N, upgrades = {...}, return_point = { kind, row, x, cells } }`. `cells` — клетки ряда точки возврата (5 строк).
- Загрузка: `sys.load` → `core/save_schema.validate` → валидная таблица или сброс с понятным сообщением.
- Запись: при установке лагеря, прохождении чекпоинта, выходе из лагеря, покупке, уходе в фон.

## 11. Тесты и инструменты

- `tests/run.lua` запускает все тесты ядра, без Defold.
- `tests/registry_test.lua` проверяет реестры (`docs/ENTITY_REGISTRY.md` §5).
- `tools/build_balance.py` генерирует `core/data/balance.lua` (из balance/balance.csv) и `core/data/design.lua` (из design/design.csv). Флаг `--check` падает при расхождении с CSV.
- Проверка сборки и загрузки коллекций — в редакторе 1.14.0.

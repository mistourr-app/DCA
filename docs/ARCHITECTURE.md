# Архитектура проекта (Defold 1.14.0)

Игра: мобильный пошаговый бесконечный dungeon crawler (см. `GDD.md`). Прототип без графики: заглушки-прямоугольники и текст.

---

## 1. Принципы

1. **Ядро отделено от движка.** Правила игры — в `core/`, чистый Lua без Defold API. Скрипты Defold связывают ядро с экраном.
2. **Мир бесконечен, память ограничена.** В памяти окно рядов и клетки ряда точки возврата. Ряды выше точки возврата генерируются по требованию из `row_seed(world_seed, respawn_count, y)` (GDD §11).
3. **Сущности через реестр.** Типы клеток, врагов, экипировки, боссов и рядов добавляются записями в реестр, без правок ядра (`docs/ENTITY_REGISTRY.md`).
4. **Данные — только из CSV.** Числа правил — из `core/data/balance.lua`, презентационные числа, читаемые `core/`, — из `core/data/design.lua`; оба генерируются (`docs/BALANCE.md`).
5. **Физика не используется.** Поле — сетка, попадания считаются по координатам.
6. **Одна игровая коллекция.** Мир, лагерь и арена босса — состояния одного мира, а не отдельные уровни. Переходы не требуют выгрузки мира.
7. **Юзер-центричность.** Всё, что можно настроить (числа, цвета, тайминги, размеры), владелец видит и правит в инспекторе Defold, не трогая код. Код хранит только то, что редактор не умеет представлять. Правило — `docs/AI_CODING_RULES.md` §0.

## 3. Слои и правило зависимостей

Детали Defold-слоя — `docs/DEFOLD_INTEGRATION.md`.

```
collections, game_objects, gui   (Defold-скрипты)
            │
            ▼
        scripts/                 (хелперы Defold, без игровой логики)
            │
            ▼
        core/                    (правила игры)
            │
            ▼
        core/data/*.lua          (сгенерировано)
```

Запрещено:
- `core/` вызывает `go.*`, `msg.*`, `gui.*`, `sys.*`, `factory.*`, `render.*`, `timer.*`.
- `game_objects/` напрямую меняет состояние мира. Только через сообщения в `world`.
- Скрипты одной коллекции напрямую читают поля друг друга. Только сообщения.
- `core/registry/*` импортирует `core/data/*.lua`, но не `core/run.lua`. Обработчики получают контекст `ctx`, а не модуль хода.

## 4. Состояния приложения

```
WORLD  (бесконечный мир; ход игрока; точка возврата)
  ├─▶ CAMP  (лагерь: восстановление, прокачка, экипировка) ─▶ WORLD
  ├─▶ BOSS  (арена босса, два ряда)                       ─▶ WORLD (через ряд чекпоинта)
  └─▶ DEATH (смерть)                                       ─▶ WORLD (в точке возврата)
```

- `WORLD`, `CAMP`, `BOSS`, `DEATH` — режимы одного мира, а не отдельные коллекции. Переход меняет режим в `core/world.lua` и показывает нужный GUI.
- Арена босса создаётся в `WORLD`, когда её ряд появляется в поле зрения: карты и босс видны до входа. Вход в `BOSS` переиспользует это состояние и актуализирует HP/позицию игрока.
- Чекпоинт — это тип ряда (`row_kinds`), а не состояние приложения.
- Владелец режима — `core/world.lua`; таблица переходов тестируется без движка.
- `world.script` отвечает за старт, загрузку сохранения и фоновый режим.

## 5. Поток данных хода

```
тап (world.script)
   │
   ▼
core/layout.lua      экранная точка -> клетка (x, y)
   │
   ▼
core/run.lua         порядок шагов GDD §5.2; возвращает список событий
   │                 при смерти: core/death.lua -> восстановление в точке возврата
   ▼
world.script         проигрывает события: анимации, текст, смена состояния клеток
```

`core/run.lua` возвращает список событий, например `{ type = "move", from = {x, y}, to = {x, y} }`. Скрипт превращает события в анимации и сообщения объектам. Ход тестируется без движка и без таймингов.

Длительности и параметры анимаций — `go.property` скриптов экрана (см. `AI_CODING_RULES.md` §12); в `design/design.csv` только числа, которые читает `core/`.

## 6. Ряды, окно и память

- **Окно рядов:** `core/world.lua` держит ряды от `current_row − W` до `current_row + W` (W — в CSV). Ряды вне окна выгружаются из памяти и генерируются заново по требованию.
- **Seed ряда:** `core/row_seed.lua` — `seed(world_seed, respawn_count, y)`. Один и тот же ряд всегда генерируется одинаково.
- **Ряды выше точки возврата:** после возрождения пересоздаются (`respawn_count` растёт). Журнала изменений нет (GDD §11).
- **Визуальные объекты:** карты создаются фабрикой для рядов в окне и удаляются при выходе за окно.
- **Прокрутка:** мир сдвигается по `y`, чтобы текущий ряд оставался в видимой части. Прокрутка — свойство контейнера `rows`.

Память проверяется тестами: число хранимых рядов не растёт с номером текущего ряда (`TESTING.md`).

## 7. Экран и поле

- Логические координаты: `x` 0..4 (5 колонок), `y` — номер ряда в мире (0 — стартовый, растёт вверх).
- Экранные координаты: логические 720×1560 (`screen.*` в `design/design.csv`), вписываются в окно с сохранением пропорций (`core/layout.screen_fit`); по краям допустимы поля.
- Камера: без `camera`-компонента. `render/game.render_script` строит content-проекцию мира и GUI с учётом `window.get_safe_area()`. Прокрутка — сдвиг контейнера рядов.
- Ввод: `action.screen_x/screen_y` (реальные пиксели окна) переводятся в логические тем же fit-преобразованием, поэтому тап совпадает с клеткой при любом размере окна и safe area.
- HUD — отдельный GUI (`hud.gui`) с `adjust_reference = DISABLED`: узлы остаются в координатах 720×1560 и масштабируются общей проекцией. Верхняя и нижняя полосы экрана закрыты чёрными градиентными фейдами (GUI-узлы с динамической текстурой), под ними ряды въезжают и уходят при прокрутке.
- Под HUD зарезервированы две строки туториала (`hint`); текст в них пока не выводится.
- Слой угроз (GDD §5.4) считается в `core/highlight.lua` и рисуется полупрозрачными прямоугольниками (`bar_factory`) поверх клеток, под персонажами и содержимым. Оверлей ужимается на толщину рамки карты (`geom_cfg.outline_width`): подсветка закрывает подложку, но не обводку. Клетка игрока в поле зрения подсвечивается. Пересчёт — при каждой перерисовке окна.

## 8. Коллекции и объекты

- `world.collection` — контейнер рядов (`rows`), `world` (несёт `world.script`), `hud` (GUI-компонент).
- Лагерь и смерть — GUI-состояния поверх мира (`hud.gui`). Мир не выгружается.
- Босс: объекты арены создаются при входе в режим `BOSS` и удаляются при выходе.
- Фабрики: карты (`card_factory`), обводок/угроз (`bar_factory`), цифр (`popup_factory`).
- Одна карта — один прототип `card.go`, вид задаётся данными (тип → вид), см. `docs/DEFOLD_INTEGRATION.md`.
- Имена объектов стабильны и не полагаются на автогенерацию.

---

## 9. Ввод

- `on_input` — в скриптах, которые принимают ввод: `world.script` (поле). GUI-кнопки HUD обрабатывает `hud.gui_script`.
- Если тап обработан, вернуть `true`, иначе `false`.
- Во время хода ввод блокируется флагом состояния, а не проверкой анимаций.
- Тап вне поля и вне кнопок игнорируется.

## 10. Сохранения

Сохраняется (GDD §18): золото, прокачка, точка возврата и клетки её ряда. Seed мира и `respawn_count` не сохраняются: при каждом запуске начинается новый мир.

- Файл: `sys.save` через `scripts/saves.lua`.
- Структура (версия 3): `{ version = 3, gold = N, upgrades = {...}, return_point = { kind, row, x, cells } }`.
- Загрузка: `sys.load` → `core/save_schema.validate` → валидная таблица или сброс с понятным сообщением.
- Запись: при установке лагеря, прохождении чекпоинта, выходе из лагеря, покупке, уходе в фон.

## 11. Тесты и инструменты

- `tests/run.lua` запускает все тесты ядра, без Defold.
- `tests/registry_test.lua` проверяет реестры (`docs/ENTITY_REGISTRY.md` §5).
- `tools/build_balance.py` генерирует `core/data/balance.lua` (из `balance/balance.csv`) и `core/data/design.lua` (из `design/design.csv`). Флаг `--check` падает при расхождении с CSV.
- `tools/check_defold_files.py` — кодировка и BOM файлов Defold.
- `tools/check_requires.py` — корректность `require()` в `core/`.
- Проверка сборки и загрузки коллекций — в редакторе 1.14.0.

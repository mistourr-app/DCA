# Правила для ИИ-агента, пишущего код

Обязательны для любого кода в проекте. Если правило конфликтует с задачей, сначала явно сообщить об этом, а не обходить правило молча.

Версия движка: **Defold 1.14.0** (см. `docs/ENGINE_DEFOLD.md`). Все API сверять с manual этой версии. Не использовать API, которого нет в manual, и не выдумывать функции.

---

## 0. Главный принцип: разработка юзер-центрична

Игру настраивает владелец в редакторе Defold, а не программист в коде. Всё, что можно увидеть и покрутить (цвет, размер, длительность, отступ, слой, текст, скорость), обязано быть доступно в инспекторе редактора. Код — только для того, чего редактор не умеет представлять.

Проверка перед сдачей: открой проект в Defold, найди параметр в инспекторе и измени его, не трогая `.lua`/`.script`. Не нашёл — задача не сделана.

Порядок выбора места для нового числа:

1. `go.property` + явное значение в `.go`/`.collection` — основной путь для всего, что видно на экране.
2. `design/design.csv` → `core/data/design.lua` — если число читает `core/` (там нет Defold API).
3. `balance/balance.csv` → `core/data/balance.lua` — числа правил, а не оформления.
4. Константа в коде — только если редактор физически не может это представить. Тогда: одно именованное место, комментарий «почему не property» и тест, который ловит поломку.

Жёсткие требования:

- Значение обязано быть видно в инспекторе: дефолт `go.property` в скрипте или явный `properties` в `.go`/`.collection`. Оба места редактор показывает и правит; скрытым считается только литерал в `.lua`/`.script`.
- У прототипов (`card.go`, `popup.go`) свойства заданы явно в `.go`: файл прототипа описывает его вид целиком, без похода в скрипт. У конфигов на `world.go` значение живёт в дефолте `go.property`, а `.collection` переопределяет его только когда инстансу нужно другое.
- Правка значения в инспекторе не должна требовать правки кода. Если для этого надо менять `.lua` — параметр спрятан неправильно.
- `go.property` в `.gui_script` запрещён движком: параметры HUD приходят сообщением из `flash_cfg.script` (раздел 12). Это исключение движка, а не разрешение прятать числа в код.
- Скрытые презентационные числа в `scripts/view/*.lua`, `collections/world.script` и `.script`-файлах — дефект. Нашёл такое при правке файла — вынеси в property (в том же изменении, если правка рядом).
- Не дублировать в коде то, что уже задано в редакторе: значение из `.go` читается, а не переписывается литералом в скрипте.

Единственное задокументированное исключение — **порядок z**. Это структурная константа: если дать слои крутить, вернётся баг «подсветка клетки над картой» (сортировка уже ломалась дважды). Слои живут в одном месте — `scripts/view/layers.lua`, порядок проверяет `tests/view/layers_test.lua`, диапазон `[-1..1]` — ограничение движка (`docs/ENGINE_DEFOLD.md`).

## 1. Общие принципы

1. **Логика отделена от движка.** Всё, что описывает правила игры (сетка, видимость, бой, AI, экономика, прокачка, генерация рядов, лагерь, смерть, журнал), живёт в `core/`. Модули `core/` не обращаются к `go.*`, `msg.*`, `gui.*`, `sys.*`, `factory.*`, `collectionfactory.*`, `render.*`, `resource.*`, `camera.*`, `timer.*`. Допустим только `vmath` (чистая математика). Модули `core/` тестируются без движка.
2. **Скрипты Defold тонкие.** `.script` и `.gui_script` занимаются только связкой: получают сообщения, зовут `core/`, двигают объекты и обновляют GUI.
3. **Нет магических чисел.** Источники чисел — раздел 12. Литералы допустимы только для индексов, нуля/единицы и структурных констант (например, `0`, `1`, `-1` в сдвигах координат, константы слоя z).
4. **Нет глобальных переменных.** Каждая переменная объявлена через `local`. Исключение: `M` в модуле возвращается таблицей, глобальные таблицы не создаются.
5. **Не менять чужой код без причины.** Перед правкой файла прочитать его целиком и найти существующие функции, которые можно переиспользовать.
6. **Минимальный объём.** Не добавлять функции, поля и абстракции «на будущее». Не добавлять обработку ошибок для сценариев, которые не могут случиться.
7. **Комментарии.** Только там, где нельзя понять код по имени. Комментарии на русском, идентификаторы на английском.
8. **Сущности через реестр.** Новый тип клетки, врага, экипировки, босса или ряда добавляется записью в `core/registry/` и строками в CSV. В ядре нет `if type == ...` по конкретным типам. Правила — `docs/ENTITY_REGISTRY.md`.
9. **Язык игры — английский.** Любой текст, который видит игрок (надписи, кнопки, сообщения, причины отказов в событиях, `label` в реестрах), пишется по-английски. Русский допустим только в комментариях, документации и сообщениях разработчика (`assert`, `print`, тесты). `label` в реестре и значения `label` в CSV — английские.

## 2. Lua в Defold

Defold использует **LuaJIT**, синтаксис **Lua 5.1**. Общий Lua state включён всегда (с 1.14.0), значит глобали из одного скрипта видны в других скриптах. Поэтому глобалов нет вообще.

Запрещено:
- Синтаксис Lua 5.2+: `goto`, `//` (целочисленное деление), `bit32`, `utf8` без проверки доступности, `table.pack`/`table.unpack` вместо `unpack`.
- Битовые операции через операторы (`&`, `|`, `~`) — их нет. Использовать модуль `bit` (доступен в LuaJIT), если он реально нужен.
- `require` с путями через `/` или с расширением: только точки, без `.lua`. Пример: `require("core.grid")`.
- `setfenv`, `getfenv`, `loadstring` (это 5.1, но не нужны: не использовать).
- Изменение таблиц во время `pairs`-итерации (добавление/удаление ключей). Собрать ключи, затем менять.
- `#t` на таблицах с дырками. Массивы без `nil`.

Обязательно:
- Модуль: `local M = {} ... return M`.
- Константы таблицами, объявленными `local` в начале модуля, в UPPER_CASE.
- Для проверки типа использовать `type(x) == "number"`, не сравнивать с `"number"` через `tostring`.
- Для сравнения float использовать эпсилон, если сравнение не целочисленное.
- Числа в координатах клеток — целые (`math.floor`/`math.ceil` при расчётах).

## 4. Сообщения и связь между объектами

- Имя сообщения — строковый литерал: отправитель передаёт его в `msg.post`, получатель сравнивает `message_id == hash("...")` в `on_message`. Строку не дублировать по коду, имя стабильно и в snake_case.
- Адресаты через `msg.url()` или `go.get_id()`. Хранить `url` в `self`, не собирать строку каждый кадр.
- `msg.post` не вызывать в цикле `update` без необходимости. События поля (клик, смерть врага) — редкие, допустимо.
- В `on_message` использовать диспетчеризацию через таблицу-обработчик, а не длинный `if/elseif`, если обработчиков больше трёх.
- Не передавать в сообщениях большие таблицы, если можно передать id.
- Не отправлять сообщение самому себе для синхронного действия — вызывать функцию напрямую.

## 5. Жизненный цикл скриптов

- `init(self)`: получить ссылки (`msg.url`, `go.get_id`), инициализировать `self`-поля. Никакой тяжёлой логики.
- `final(self)`: отписаться от таймеров (`timer.cancel`), отменить анимации (`go.cancel_animations`), освободить ссылки на ресурсы.
- `update(self, dt)`: только то, что меняется каждый кадр. Не создавать таблицы и строки внутри `update` без необходимости: переиспользовать буферы.
- `on_input(self, action_id, action)`: возвращать `true`, только если ввод поглощён. Иначе `false`/`nil`.
- Игровая логика хода выполняется по событию (клик), а не по `update`. `update` нужен только для анимаций и интерполяции.
- `go.property` объявлять только для данных, которые нужно редактировать в редакторе. Внутреннее состояние — в `self`.

## 6. Анимации и таймеры

- Визуальные переходы: `go.animate`, `gui.animate`. Для последовательностей: callback-цепочка либо `go.animate` с `complete_function`. Не блокировать логику ожиданием.
- Отмена: `go.cancel_animations(url, property)` до запуска новой анимации на то же свойство.
- Задержки: `timer.delay(delay, repeat, callback)`, при `final` отменять через `timer.cancel`.
- Ход игры не должен зависеть от длительности анимации. Логика выполняется сразу, анимация только показывает результат. Если логике нужно дождаться анимации, использовать явную очередь состояний, а не `timer.delay` с магическим временем.
- Длительности и параметры анимаций — `go.property` скрипта, который их проигрывает (`anim_cfg.script` — `move_ms`, `card.script` — `lunge_ms`/`fall_ms`/`flash_ms`/`lift_scale`, `popup.script` — цифры, `hud.gui_script` — вспышка). В `balance.csv` их быть не может: это не геймплей. Числа, которые читает `core/`, — в `design/design.csv`.

## 7. Ввод (тап по клетке)

- Вся игра управляется тапами. Обрабатывать `action_id == hash("touch")` и `action.pressed`.
- Экранные координаты переводить в координаты поля через `camera.screen_xy_to_world` (если камера используется) либо через собственную функцию в `core/grid`.
- Попадание по клетке: вычислять индекс из координат в `core/`, а не через физику (физика отключена).
- Блокировать ввод во время хода: флаг состояния в `world.script`, а не проверка анимации.
- Для GUI-кнопок использовать `gui.pick_node`, не перебирать узлы вручную.

---

## 8. Ресурсы и объекты

- Спавн объектов: `factory.create` (один объект), `collectionfactory.create` (группа). Ссылки на созданные объекты хранить в `self`, удалять через `go.delete`.
- Не спавнить и не удалять объекты каждый кадр. Клетки создаются для рядов в окне (`core/world.lua`) и удаляются при выходе из окна. Для клеток арены — пул.
- Ресурсы (`.atlas`, `.tilesource`, шрифты) загружать декларативно в компонентах, не через `resource.*` в горячем коде.
- Имена объектов в коллекциях: стабильные id (`world`, `rows`, `hud`, `cell_<x>_<y>`). Не полагаться на автогенерируемые.
- Мир — одна коллекция `world`. Экраны лагеря и смерти — GUI поверх мира. Босс — объекты арены, создаются при входе в режим босса и удаляются при выходе. Не загружать несколько миров одновременно.

## 9. Сохранения

- Только через `sys.save(filepath, table)` и `sys.load(filepath)`.
- Путь к файлу в `scripts/saves.lua`, константа. Не хардкодить путь в нескольких местах.
- Сохранение всегда проходит валидацию: `core/save_schema` проверяет типы, отбрасывает неизвестные и отрицательные ключи. Загруженные данные никогда не используются без валидации.
- Версия схемы хранится в сохранении (`version`). При несовпадении — миграция в `core/`, либо сброс с понятным сообщением.
- Сохранять при установке лагеря, прохождении чекпоинта, выходе из лагеря, покупке и уходе в фон. Не каждый кадр.
- В сохранение не пишется состояние текущего хода и анимации (см. GDD §18).

## 10. Производительность (мобильные устройства)

- Переиспользовать `vmath.vector3` и таблицы в горячих циклах: создавать один раз.
- Не использовать конкатенацию строк в `update`. Строки собирать заранее или кэшировать.
- Не вызывать `go.get`/`go.set` для одного и того же значения многократно за кадр: кэшировать в `self`.
- Обновлять GUI-текст (`gui.set_text`) только при изменении значения.
- Мир бесконечный: в памяти только окно рядов и журнал (GDD §11). Не хранить весь пройденный мир. Профилирование через `Profiling` подтверждает размер окна.
- Включать `engine.fixed_update_frequency` только если нужен fixed_update. По умолчанию не нужен.

## 11. Именование

| Что | Стиль | Пример |
|---|---|---|
| Файлы Lua и Defold | snake_case | `row_gen.lua`, `world.script` |
| Функции и переменные | snake_case | `get_visible_enemies`, `player_hp` |
| Таблицы-модули | `M` | `local M = {}` |
| Константы | UPPER_CASE | `MAX_COLUMNS`, `CELL_TYPE.WALL` |
| Enum-подобные значения | UPPER_CASE в таблице | `CELL_TYPE.HEAL`, `PHASE.DUNGEON` |
| Тип врага (ключ) | `TYPE_N` (как в DR) | `TYPE_1` |
| Лейблы для игрока | UPPER_CASE, из balance | `ARCANIST` |
| Сообщения | snake_case строка в hash | `hash("cell_clicked")` |
| Коллекции и объекты Defold | snake_case | `world.collection`, `card.go` |
| ID объектов в коллекции | snake_case | `world`, `rows`, `card_3_4` |

Координаты: `x` — колонка (0..4), `y` — ряд (0 — нижний). Всегда в этом порядке, всегда `x, y` (не `row, col`).

## 12. Источники чисел

Правило: **всё, что может быть `go.property`, — `go.property`** (главный принцип — §0).

| Что за число | Где живёт | Где правится |
|---|---|---|
| Правила игры: HP, урон, шансы, цены, кривые, период боссов | `balance/balance.csv` → `core/data/balance.lua` | текстовый редактор / таблицы; код читает только generated-файл |
| Числа, которые читает `core/` (геометрия `screen.*`, `screen.threatAlpha`) | `design/design.csv` → `core/data/design.lua` | то же. Причина: `core/` не видит Defold и `go.property` |
| Экран: длительности анимаций, палитра, размеры обводок/пунктира, разброс цифр | `go.property` скрипта экрана (`anim_cfg.script`, `geom_cfg.script`, `flash_cfg.script`, `card.script`, `popup.script`) | инспектор Defold (значение пишется в `.go`/`.collection`) или тот же файл руками |
| Цвета палитры (16 ролей) | узлы `gui/palette.gui` (`enabled: false`), список ролей — `scripts/view/palette.lua` | GUI-редактор: пикер RGBA/hex у узла. Причина: у `go.property` пикера нет, только X/Y/Z/W (`docs/ENGINE_DEFOLD.md` §3b) |

- Сгенерированные файлы не редактировать руками. Изменение баланса: править CSV → `python tools/build_balance.py` → `lua tests/run.lua`.
- Новый параметр добавляется сначала в источник (CSV или объявление property), потом в код. Код не читает параметр, которого нет в источнике.
- Числовые литералы в скриптах экрана, кроме структурных констант (слои z, доли вида 0.5), запрещены — объявляй property.
- Слои z (`Z_CELL` и т.п.) — константы кода: это порядок отрисовки, не настраиваемый параметр. Живут в одном месте — `scripts/view/layers.lua`; порядок фиксирует `tests/view/layers_test.lua`.
- `debug_seed` (`world.script`): `0` — новый мир при каждом запуске; ненулевое значение фиксирует seed для тюнинга. Ненулевое значение не коммитить.
- Правило DR: balance-данные вытягиваются через геттеры, которые валидируют наличие ключа и бросают ошибку при отсутствии (не молчаливый `nil`).

## 13. Тесты

- Для каждого модуля `core/` с логикой — файл `tests/<name>_test.lua`.
- Тесты не используют Defold API. Запуск: `lua tests/run.lua` (LuaJIT либо Lua 5.1).
- Обязательные тесты: сетка и соседство, видимость (стены блокируют), стоимость прыжка, урон (= текущий HP), окно силы врагов, цены прокачки, валидация сохранений, генерация ряда по seed (воспроизводимость), журнал и точка возврата, лагерь и оплата, смерть без фарма, реестры (`docs/ENTITY_REGISTRY.md`).
- Багфикс сопровождается тестом, который падал до исправления.
- Не удалять и не ослаблять существующие тесты ради прохождения.

## 13a. Кодировка и формат файлов (обязательно)

- Все текстовые файлы: UTF-8 **без BOM**, перевод строки LF в репозитории.
- Defold падает на BOM: `Expected identifier. Found '﻿'`. Поэтому при создании файла через PowerShell не использовать `Set-Content -Encoding UTF8` и `[Text.Encoding]::UTF8` (они пишут BOM). Записывать через `[IO.File]::WriteAllText(path, text, New-Object Text.UTF8Encoding($false))`.
- После любой записи файлов Defold-формата выполнять `python tools/check_defold_files.py`. Код возврата 1 — файл не коммитить.
- Тексты, которые видит игрок, — только английский (правило 9).

## 14. Что нельзя делать

- Править файлы в `build/`, `.internal/`, сгенерированные `*.projectc`, `*.collectionc`, `*.goc`.
- Менять `game.project` без явной причины. Изменения настроек — отдельным коммитом с объяснением.
- Использовать `os.*`, `io.*` для игровых данных. Для файлов игры только `sys.save`, `sys.load`, `sys.load_resource`.
- Использовать `sys.get_sys_info` и подобные для игровой логики (зависит от устройства).
- Добавлять сторонние библиотеки без согласования. Допустимы только библиотеки из Defold Asset Portal и только после проверки совместимости с 1.14.0.
- Использовать устаревшие API (проверять deprecated в manual 1.14.0).
- Отключать тесты, lint или проверки баланса, чтобы код прошёл.

## 15. Чек-лист перед сдачей изменения

1. Логика в `core/`, Defold API не просачивается в неё.
2. Нет новых литералов-чисел баланса.
3. Нет глобалов (проверить `local` у всех новых переменных).
4. Имена сообщений не дублируются: один отправитель и один получатель (`message_id == hash("...")`).
